# Changelog

All notable changes to `@astramindapp/mcp-server` are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.25.0] — 2026-09-16

### Added — full app-suite coverage: 31 tools → 44

- **13 new tools**, one per MIND app that wasn't yet reachable over MCP: `mind_mindmap` (MIND Mind Map), `mind_moneymind` (MoneyMIND personal finance — 37 actions), `mind_budget` (13-week cash-flow planner), `mind_sheets` (Airtable-style tables), `mind_email` (Email Manager, ⚠️ `send` is outward), `mind_checklists` (Kanon checklists — templates, runs, `toggle_item`, `progress` rollups; **replaces** the older, narrower `mind_checklists` that used `list_templates`/`create_template`/etc. action names — the action set now matches the Kanon REST API verbatim), `mind_sign` (e-signature, ⚠️ `send`/`resend` are outward), `mind_invoices` (Invoice Agent, ⚠️ `invite` is outward), `mind_books` (MIND Books accounting), `mind_timer` (Tempo time tracking), `mind_forms` (Quill lead-capture forms), `mind_library` (personal bookshelf), and `mind_share` (create/list/list_all/revoke share links for a MIND document — a hosted-only tool this pass discovered, mirrored from the existing `_t_mind_share` handler in `backend/routes/mcp_server_routes.py` that had no stdio-server counterpart until now).
- Every new tool's `action` enum and argument names are taken verbatim from the underlying FastAPI route's Pydantic body fields / query params / path params — no invented synonyms. Two unavoidable naming collisions (a REST body field also literally named `action`, colliding with the tool's own dispatch key) are resolved by renaming the *argument* and documenting the mapping in the tool description: `mind_moneymind`'s `rule_create` body field `action` → arg `rule_action`; `mind_email`'s `action` operation's body field `action` → arg `email_action`.
- New generic dispatch helper `MindClient.call()` (`src/mind-client.ts`) builds the path (substituting `{param}` placeholders), query string, and JSON body from one flat args object plus explicit per-action field lists — the same pattern as the existing per-tool `client.xxx()` methods, generalized so ~150 new REST actions didn't need ~150 bespoke client methods.
- `backend/data/mcp_tools.json` is now regenerated by `scripts/export-catalog.mjs` (`npm run export-catalog`) instead of hand-edited — it spawns the built stdio server, drives `initialize` + `tools/list` over JSON-RPC, and rewrites the catalog file in place while preserving every top-level key the hosted `/mcp` handshake depends on (`icons`, `websiteUrl`, etc.). It also derives the hosted `instructions` string's TOOL MAP section (and the AUTH line's "sees the other N" admin-tool count) live from the current tool catalog, so neither can silently go stale again.
- `.github/workflows/publish-mcp-server.yml` — the post-publish "confirm the version is live on the registry" poll widened from 20×10s to 60×10s; npm registry propagation occasionally exceeds 200s.
- README + package counts corrected to **44 tools, 384 actions** (sum over every tool of `len(inputSchema.properties.action.enum)`, or 1 for a tool with no `action` enum — the same method the public site and `llms.txt` use). Fixing this also caught three pre-existing stale per-tool counts in the README table (`mind_folders` 6 → 7, `mind_life` 13 → 16, `mind_agents` 21 → 25) and six tools that were missing from the table entirely (`mind_focuses`, `mind_folder_routes`, `mind_folder_suggest`, `mind_osint`, `mind_social_analytics`, `mind_personas`) — none of that predates this release, it was drift already sitting in the table.

### Fixed — mind_mindmap's write-adjacent actions were never callable over MCP

- `from_prompt`, `from_project`, `share`, and `unshare` are deliberately JWT-only in the backend (`backend/routes/mindmap_routes.py`, enforced by `backend/tests/test_mindmap_apikey_auth.py` written 2026-09-15) — granting access, publishing to the web, and spending AI-generation credits stay human-only, gated behind a browser session. An MCP/API-key caller could never actually use them, so they're removed from `mind_mindmap`'s `action` enum (now `list`, `get`, `create`, `update`, `delete`, `get_shared`) rather than left in the schema as calls that always 401. The tool description now says outright that sharing, collaborators, and AI generation stay in the web app at m-i-n-d.ai/#/mind-map.

## [0.24.1] — 2026-09-16

### Fixed

- **Default base URL is `https://www.m-i-n-d.ai`.** The apex `https://m-i-n-d.ai` answers every path with a 307 to www, and HTTP clients drop the `Authorization` header when a redirect crosses hosts — so a valid key sent to the apex came back 401 and agents reported the key as invalid (Grok Bot, Muse, 2026-09-16). `MIND_BASE_URL` still overrides it. Applies to `mind-mcp`, `mind-mcp-setup`, the `.mcpb` bundle default, and the docs.

## [0.24.0] — 2026-09-08

### Fixed — cold agent install: no hang, no "could not determine executable to run"

- **`npx -y <pkg>` resolves the bin named after the package's LAST path segment** (`mcp-server`) — so `npx -y @astramindapp/mcp-server` alone failed, and the previously-documented invocation that appended `@latest` plus a trailing `mind-mcp-setup` just passed it as an *argument*, not a bin selector, so it also failed with "could not determine executable to run" on every published version. Added a third bin alias, `"mcp-server": "dist/cli.js"`, so the package resolves cold. The working form on every version is `npx -y --package=@astramindapp/mcp-server mind-mcp-setup` (or `mind-mcp`).
- **`mind-mcp-setup --help` used to print usage and then run the wizard anyway** — opening a browser and blocking forever in a non-TTY shell. `src/setup.ts` now: exits 0 immediately on `--help`/`-h` without touching the wizard; detects a non-interactive shell (`!process.stdin.isTTY`, `CI` set, or `MIND_NONINTERACTIVE=1`) and, if no key was resolved from `--key` or `MIND_API_KEY`, prints the three non-interactive options and exits 2 instead of opening a browser or blocking on a readline prompt; if a key WAS resolved non-interactively, it writes every detected tool's config with no prompts.
- **`mind-mcp` with no `MIND_API_KEY` only printed one line and stopped** — `src/cli.ts` now also handles `--version`/`-v` (reads the version from `package.json`, no `resolveJsonModule` dependency), `--help`/`-h`, and a `setup`/`mind-mcp-setup` first argument (delegates to the setup wizard with the remaining args). The missing-key message now lists, in order: the no-install remote connect command, the working `npx --package=` setup form with `--key`, and where to mint a key.
- **`src/integration-guide.ts`** — the MCP-host row's install command corrected to the working `npx -y --package=@astramindapp/mcp-server mind-mcp-setup` form.
- **Docs** (`README.md`, `frontend/public/mcp.html`, `frontend/public/llms.txt`, `skills/mind/SKILL.md`) — every occurrence of the broken `@latest`-plus-`mind-mcp-setup` invocation replaced with the working `--package=` form; README troubleshooting entry now explains the last-path-segment rule; `skills/mind/SKILL.md` Setup section leads with the remote no-install connect, then the key path via `npx -y --package=...`, and drops the stale `npm install -g` step.
- **Security** — `.mcpregistry_github_token` and `.mcpregistry_registry_token` were tracked in git despite being `.gitignore`d (force-added at some point); removed from the index (`git rm --cached`, files kept on disk). **Both must be rotated** — they were live secrets in git history.
- **`.github/workflows/publish-mcp-server.yml`** — new publish workflow living at the true source (this repo, `mcp-server/`), adapted from the public mirror's `publish-npm.yml`, so a release no longer depends on the stale `theastraway/mind-mcp-server` mirror.

### Added — MCP is retrieval; the connecting model reasons

- **`retrieve_only` on `mind_query`.** MIND now returns raw knowledge-graph context and the connecting model (Claude/Grok/GPT) writes the answer. This skips MIND's generation LLM **and** the keyword-extraction LLM, so the path costs **0 credits**. Backed by a new `retrieve_only` field on `POST /developer/v1/query`.
- **Defaults differ by surface, on purpose.** The MCP tool defaults to `retrieve_only=true`; the HTTP API field defaults to `false`. Existing REST clients, in-app MIND chat, MoneyMIND and the SDSU/Revolut demo surfaces all keep receiving a synthesized answer with no change.
- **Per-call override.** Pass `retrieve_only=false` to `mind_query` to have MIND synthesize the answer itself (spends credits) — so agents that relay MIND's prose verbatim are not silently broken.
- **Tool description and server `instructions` updated** to state plainly that the return value is retrieved context, not a finished answer. Without this an agent will hand raw chunks back to the user as if MIND had written them.

### Notes

- **`mind_context` deliberately still synthesizes.** It is a boot briefing whose value is the digest; five sections of raw chunks would put a large undifferentiated dump at the top of every session. Make it cheaper by caching or a cheap instruct model, not by dropping synthesis.
- **`mind_trader`** ships to npm for the first time in this release. It has been registered in `src/server.ts` since 2026-07-14 but was never published.

## [0.23.0] — 2026-07-01

### Fixed — the version agents actually see

- **Agent-facing version was stuck at `0.17.0`.** Every publish bumped `package.json` (which reached 0.22.0) but not the `serverInfo.version` string reported in the MCP `initialize` handshake, so every connecting agent — local (`src/server.ts`) and remote (`backend/data/mcp_tools.json`) — was told the server was "v0.17.0". Bumped all agent-facing version strings to match `package.json` (0.23.0): `src/server.ts`, `server.json` (manifest + npm package entry), and the backend remote catalog `backend/data/mcp_tools.json`.
- **`scripts/check-version-sync.mjs`** — new build-time guard wired into `npm run build` (`build: node scripts/check-version-sync.mjs && tsc`). It makes `package.json` the single source of truth and **fails the build** if `server.json`, `src/server.ts`, or the backend remote catalog disagree — so this drift can never ship silently again.

## [0.22.0] — 2026-06-12

### Added — browser OAuth is now the default setup flow

- **`src/oauth-connect.ts` — `connectViaBrowser(baseUrl, options)`.** Full loopback OAuth 2.1 Authorization Code + PKCE (S256) flow against the MIND backend's MCP OAuth surface (`/oauth/mcp/register` → `/oauth/mcp/authorize` → `/oauth/mcp/token`). Starts a local callback server on `127.0.0.1` (OS-assigned port), dynamically registers a public client named "MIND Setup CLI" (RFC 7591), opens the consent page in the default browser (macOS `open` / Windows `start` / Linux `xdg-open`, with a printed-URL fallback and `MIND_CONNECT_NO_BROWSER=1` opt-out), verifies `state` on the callback, exchanges the code, and returns the minted `mind_` API key. Styled success/error pages in the browser tab; 5-minute timeout. Node built-ins only — zero new dependencies.
- **`mind-mcp-setup` default mode is now browser connect.** Run the wizard, the browser opens, click **Connect** on m-i-n-d.ai, and the wizard receives your API key automatically — no manual key copying. The existing manual-paste path stays available via `--key [value]`, as the fallback when the browser flow fails, and via the `MIND_API_KEY` env convenience. Tool detection and config writing are unchanged.
- **`test/oauth-connect.test.mjs`** — `node --test` suite with a dependency-free mock OAuth server doing real S256 PKCE verification: happy-path (key returned, state round-trip, DCR payload) + negative (tampered `state` → 400 page + flow rejection, token endpoint never called).

### Changed
- **README quick start reordered**: (1) one-paste remote connect `claude mcp add --transport http mind https://m-i-n-d.ai/mcp`, (2) the `mind-mcp-setup` browser-connect wizard via `npx -y @astramindapp/mcp-server@latest` for local stdio installs, (3) manual API-key flow as the last alternative. (Superseded 0.24.0 — see below: that npx form fails with "could not determine executable to run"; use `npx -y --package=@astramindapp/mcp-server mind-mcp-setup`.)

### Backend pairing
Pairs with MINDapp `backend/routes/mcp_oauth_routes.py` (OAuth 2.1 + PKCE + RFC 7591 DCR; access tokens are standard `mind_` API keys). Loopback `http://127.0.0.1:<port>/callback` redirect URIs are accepted by the backend's public-client policy.

## [0.16.0] — 2026-05-26

### Changed
- **`mind_remember` — `type` enum now spells out PRIVATE vs PUBLIC.** Added `feed_post` as the correct name for a public social-media post; kept `thought` as a deprecated alias that maps to the same backend call so every existing agent continues to work unchanged. The tool description now opens with a ⚠️ block explaining that `document` and `entry` are PRIVATE to the user's knowledge graph while `feed_post` writes to the user's PUBLIC social feed, and that agents must NEVER use `feed_post` unless the user explicitly said "post", "share", "tweet", "feed", or "thought to my feed". Deploy logs, PR notes, work outcomes, session summaries, and all agent activity belong in `entry`.
- **`mind_social` — `create_thought` description carries the same explicit-trigger rule.** Same caveat in the tool description so agents see it whichever surface they reach for.
- **`SERVER_INSTRUCTIONS` (mind://integration-guide) — added a PRIVATE vs PUBLIC block to the session protocol** so every newly-connecting MCP client sees the rule in the `initialize` response, before it picks a tool.

### Why
The word "thought" reads as "internal scratch note" to every LLM, but in MIND it's a PUBLIC social-media post. AI agents kept writing deploy logs / PR notes / work updates as `thought` and accidentally publishing them to the user's public feed. Naming was the root cause — `feed_post` fixes the surface so the type the agent picks matches what the agent meant. The deprecated `thought` alias keeps every existing agent and integration working unchanged.

### Backend pairing
Paired with new MINDapp route `backend/routes/feed_post_routes.py` which mounts the existing `/thoughts` handlers under `/feed_posts` (production-additive — both prefixes share the same handlers and MongoDB collection).

## [0.11.0] — 2026-05-19

### Added
- **`mind_tickets` — the agent ticket queue.** Every agent in the Command Center carries a ticket queue: client feedback, critique, ideas, feature requests, and bugs. This new tool gives MCP clients full control over it — `list` (every ticket on an agent + open/total stats), `get` (one ticket plus its full comment thread), `create` (file a ticket — auto-assigns to the Ernie triage agent), `comment` (answer a ticket by adding to its thread), `update` (triage — change status / priority / kind / reassign), `resolve` (shortcut: mark a ticket resolved), and `delete` (remove the ticket, its comments, and its mirrored MIND Life task). 7 actions. Backed by `/admin/agents/{slug}/tickets`; admin API key required.
- `mind_agents` → **`list_query`** parameter on the `list` action — free-text search across an agent's slug, name, description, and tags (case-insensitive substring match), so a fleet of dozens is searchable without paging.
- Six typed client methods on `MindClient` — `listAgentTickets`, `getAgentTicket`, `createAgentTicket`, `updateAgentTicket`, `commentAgentTicket`, `deleteAgentTicket` — plus the `AgentTicket`, `AgentTicketComment`, `TicketStats`, `TicketKind`, `TicketStatus`, and `TicketPriority` types.

- `server.json` version corrected from a stale `0.5.3` to track the package version.

### Backend pairing
Paired with the MINDapp endpoint family `GET/POST/PATCH/DELETE /admin/agents/{slug}/tickets[/{ticket_id}][/comments]` (already live) and the new `q` query parameter on `GET /admin/agents`.
